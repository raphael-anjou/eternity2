## 1. The analog

**Primary analog: Subgraph Isomorphism / injective homomorphism with pattern as large as host, pattern of treewidth 16.** [derived mapping] Cells are pattern vertices, tiles (with rotation) are host vertices, colour matching is the adjacency relation, and "each tile once" is injectivity. The colour-only puzzle (repeats allowed) is the homomorphism problem, solvable by dynamic programming over the grid's path decomposition. Injectivity is the entire difficulty, as in the literature: homomorphism counts cost n^O(tw), injective ones cost an extra 2^k for a k-vertex pattern (Fomin, Lokshtanov, Raman, Rao, Saurabh; Amini, Fomin, Saurabh). Here k = n = 256.

**Second analog: permutation problems solved by subset dynamic programming** (TSP, Bandwidth, vertex orderings). The Bellman-Held-Karp state "set of used cities plus last city" is the transfer matrix state "set of used tiles plus frontier colours". Worst-case table: 2^n x frontier.

**Third analog: exact cover and k-dimensional matching.** Tiles x cells is a bipartite perfect matching once the colour of every edge is fixed; the colours are extra dimensions. This is the DLX formulation (ROUTES section 4, row "Exact cover / DLX").

**Fourth analog: one-row edge matching and Eulerian trails.** The frame ring alone is a cyclic 1 x 60 puzzle whose tiles cannot rotate (one grey side each). Without rotation, 1 x n edge matching is an Eulerian path problem and is polynomial [cited, Bosboom et al. 2016, section 2: "if rotations are prohibited, then 1 x n Edge-Matching Puzzle is in P [EFW11]"]. [derived] So the frame by itself is the easy case of the field, with 10^37.6 solutions (ROUTES section 5, row "Exact count of frame placements"), and the interior given the frame is cheap (ROUTES section 3). The hardness of the instance is the coupling of an easy, hugely degenerate one-dimensional problem with a 14 x 14 interior, not either part.

**What maps to what.**
- All-different over 256 tiles = injectivity = the "used set". Exact.
- Density: no analog. Worst-case theory has no parameter for "number of colours tuned so that the expected solution count is about 1". This is the main break.
- Planted solution: no analog. The field's guarantees hold for every instance; none is sharpened by a promise that a solution exists, except through isolation lemmas, which only help randomized algebraic detection that is already too expensive here.
- Fixed size: every lower bound below is asymptotic and says nothing formal about one 16 x 16 instance. They indicate which shape of exponent a general method can have, no more.

**Where the analogy breaks, in one number.** The measured tree is 2^134.4 = 2^(0.525 n), a base of 1.439 per tile. Every worst-case exact algorithm in this field for an injectivity-type problem has base 2 per element of the sieved universe, with structure-specific exceptions at 1.657, 1.496 and 1.414. A random critical instance is far sparser than the worst case the theory is built for: at the peak the tree holds about 2^68 used sets per frontier state, against C(256,135) = 2^251 possible ones.

## 3. Hardness evidence

**B1. A partial sieve never beats the tree. [derived; I found it in no paper]**
Claim. Split the tiles into a tracked set T and a sieved set U (any U, any sweep order). The hybrid runs, for each S ⊆ U, a frontier DP whose state is (frontier, used ∩ T) and in which tiles of S may repeat; the signed sum over S counts solutions. Let N_k be the number of strict partial boards at depth k and m_k the largest number of strict partial boards sharing one (frontier, full used set). Then the total number of table entries at depth k, summed over S, is at least N_k / m_k.
Proof. A strict partial board b using a set A ⊆ U of size a is a legal board of the S-run for every S ⊇ A. Inside the S-run, strict boards that collapse onto one state share the frontier and used ∩ T, so they differ only in which a-subset of S they use: at most C(|S|, a) x m_k boards per state. Summing over S, board b contributes at least Σ_{s>=a} C(u-a, s-a) / C(s, a) / m_k = Σ_{s>=a} C(u, s) / C(u, a) / m_k >= 1/m_k. The same bound holds if all S are run together by carrying a parity vector on U, since (frontier, used ∩ T, parity on U) determines the full used set of a strict board.
Reading. Tracking some tiles and sieving the rest costs at least the plain used-set DP, which is the tree divided by m. On toys m is 1.05 to 1.14 (path 1) or 2 to 4 on small palettes (path 3). On the real tiles the first-moment chance of a local rearrangement is 10^-11 per 2 x 2 block and 10^-52 globally (path 3), so m is 1 for practical purposes. This closes the family "hybrid of ROUTES rows used-set transfer matrix and inclusion-exclusion".
Assumptions: none beyond counting. Holds for the planted instance, any clue set, any fixed size.

**B2. No rank-based or representative-set compression of the used set exists. [derived from the cited frameworks]**
Both methods shrink a DP table to the rank of its compatibility matrix (Bodlaender et al. arXiv:1211.1505; Fomin et al. arXiv:1304.4626, bound C(p+q, p)). For this puzzle a partial fill with tile set A at depth k is completed only by fills using exactly the complement. The matrix M[A, B] = [A and B disjoint], with |A| = k and |B| = 256 - k, is a permutation matrix over every field: rank C(256, k), up to 2^251.7. The representative-set bound C(p+q, p) with p + q = 256 says the same. So instance-independent compression of the used set is impossible; only the instance's own sparsity (2^68 reachable sets per frontier at the peak) is available, and the tree already has it. Assumptions: none; this is linear algebra.

**B3. Generic multilinear detection cannot beat 2^k. [cited theorem]**
Koutis and Williams, section 1: "for any commutative algebra A used to evaluate the circuit C, the lengths of elements in A must be at least Ω(2^k / k) in order to solve k-MLD", and section 4: "if it can be used to detect multilinear monomials in an arithmetic circuit (even randomly), then |A| >= 2^Ω(2^k / sqrt k)"; a footnote says the bound "holds in the non-commutative setting as well". Scope: algorithms that evaluate the circuit as a black box over an algebra. Here the circuit is the colour-only transfer matrix and k = 251. Any improvement must use the structure of the circuit, which for random tiles is a random constraint network. Holds for this instance as a statement about a method class, not about the instance.

**B4. One-row edge matching has no 2^o(n) algorithm under ETH. [derived from a cited reduction plus a textbook fact not opened today]**
The Bosboom et al. reduction maps a digraph with |V| vertices and |A| arcs of in- and out-degree at most 2 to a 1 x (|V| + |A| + 1) puzzle, so n = O(|V|). The paper does not mention ETH (checked by text search). Combined with the standard fact that Hamiltonian Path on bounded-degree digraphs has no 2^o(|V|) algorithm under ETH (the paper cites Plesník's planar version; the linear-size ETH statement needs the non-planar reduction, which I did not open), this gives: no 2^o(n) algorithm for 1 x n edge matching with rotation, with a number of colours linear in n. Parameter: n = number of tiles. Assumptions that fail here: unbounded colours; adversarial instance. Meaning for the program: the 2^n factor of the used-set DP is the right shape even at frontier width 1, so no method whose only lever is the narrow frontier (width 16, or width 1 on the frame ring) can be subexponential in the number of tiles in general.

**B5. The colour-only relaxation at 17^16 has the right exponent. [derived from a cited definition and lemma]**
Marx (ICALP 2012, https://www.cs.bme.hu/~dmarx/papers/marx-mway-icalp2012.pdf) defines Grid Tiling (k x k cells, a set S_ij ⊆ [n] x [n] per cell, neighbours must agree on one coordinate), proves "Grid Tiling is W[1]-hard parameterized by k" (Lemma 1) by turning a k-clique into a k x k instance, and quotes "An f(k) n^o(k) algorithm for Clique implies that ETH fails" (Theorem 4). Hence no f(k) n^o(k) algorithm for Grid Tiling under ETH. Grid Tiling is colour-only edge matching with a separate tile list per cell (tile (x, y) shows x left and right, y top and bottom). So a colour-only board of side k with c colours and per-cell lists cannot be contracted in c^o(k). Assumption that fails here: the relaxed puzzle has one tile list for all interior cells, not one per cell, and k = 16 is fixed. I found no lower bound for the uniform-list case.

**B6. For square boards the fine-grained complexity is open. [derived; absence of a result]**
Upper bound 2^(n + O(sqrt n log c)) by subset DP. The Demaine and Demaine reduction is from 3-Partition with polynomial blow-up, so it gives no tight ETH bound. Two searches today (arXiv API by title, one web search for edge matching or jigsaw with ETH, fine-grained or parameterized, 2020 to 2026) found no paper stating an ETH lower bound or a 2^o(n) algorithm for sqrt(n) x sqrt(n) boards. `M12/literature-2026.md` section 9 records the same null.

**What the field does not have.** No average-case or planted-instance lower bound of the statistical-physics kind, and no statement about one fixed instance. All of B3 to B5 are asymptotic and conditional. B1 and B2 are unconditional but concern method classes.

## 4. Transfer candidates

**Nothing transfers as a solver.** The reason is one inequality [derived]: a method of the form (sieve terms) x (frontier work) beats the baseline only if the sieve has fewer than 2^(134.4 - 75.4) = 2^59 terms (or 2^72.5 if one counts bare row states at 61.87 bits and ignores per-state work). That is 0.235 to 0.289 bit per free tile. The cheapest injectivity mechanism known for any problem in this family costs 1 bit per element in general, 0.73 for Hamiltonicity, 0.58 for exact cover by 3-sets, 0.5 for bipartite Hamiltonicity, each from structure the puzzle does not have. And by B1 the sieve cannot be applied to part of the tiles to buy part of the gain.

Answer to the question as posed: no. The separator contributes at most the frontier (61.87 to 75.4 bits) and that part is fine; the sieve over tiles contributes 251 bits and cannot be made partial (B1), cannot be compressed by rank (B2), and cannot be evaluated generically in fewer than 2^k steps (B3). The sum is 192 bits above the baseline.

### 4.2 Why a determinant does not rescue it

[derived] For a fixed colouring χ of the 480 internal edges, the number of solutions with that colouring is the permanent of the 256 x 256 matrix A_χ[cell, tile] = "tile fits the four colours at the cell", and over characteristic 2 a permanent is a determinant, polynomial time. So the solution count is Σ_χ perm(A_χ), and a random-weight version detects a solution. The sum over χ has 17^420 x 5^60 terms. A transfer matrix sums over χ in 2^62 states only because the summand factorises over cells, and a determinant does not: expanding it cell by cell is the exterior algebra of dimension 2^256, which is extensor coding, which is the used-set DP. Björklund's determinant sums work because his sieved labels are few (n/2 or 0.73 n) and his determinant is over the whole vertex set at once with no local side constraint. I see no formulation of the puzzle in which the side constraint is light enough.

### 4.3 The one cheap check worth running, if any

Not a method; a test of B1, which is new and unrefereed. On the 4 x 4 and 5 x 5 generated boards of `M12/solve-path-1/toy.py`, which already contains a parity-mask transfer matrix: for U = the frame-edge tiles and for U = a random half of the tiles, count distinct (frontier, used ∩ T, parity on U) states per depth and compare with the strict partial-board count. Prediction: the ratio is at least 1/m at every depth (m measured there as 1.05 to 1.14) and well above 1 past the first rows. Kill line for B1: any depth with a ratio below 0.5. Cost: seconds. My odds that B1 survives: 97%. Odds that anything in this section leads to a solver: below 10^-6, and I would not spend a track on it.
