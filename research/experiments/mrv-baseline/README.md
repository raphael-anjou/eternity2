# A22: bb-mrv as a hard-ladder baseline (fresh seeds, scaling, ablation)

Preregistration: [`PREREG.md`](PREREG.md) (commit `ac13493`, pushed before any
run). New ladders recorded as hard-ladder amendment A4 (`8-c10-fresh`,
`plus2`; commit `b6daa50`), generated by `hard_ladder::instance::generate(n,
c, seed)` and checked with `hard_ladder check-instances`; existing ladder files
are byte-identical. No amendments to this preregistration. Generated boards
only; nothing here is official E2 progress, and nothing here is extrapolated to
16x16.

## Self-assessed outcome (a separate judge decides)

- Kill rule (binding, 8x8 c=10, seeds 21..50, 30 pairs): G1 PASS (paired node
  ratio bb-mrv/scb 0.147, 95% CI [0.076, 0.313]) and median paired wall-clock
  ratio 0.194 (95% CI [0.106, 0.353]), which is not above 1. The kill rule does
  not fire: bb-mrv survives as a ladder baseline candidate at that rung.
- Q2 (binding): no evidence of a growing gain. Binding slope of the median
  paired log10 node ratio against n over n = 6..10 on the c = primary + 2
  track: +0.089 per n, 95% CI [+0.065, +0.124]. The CI is not below 0.
  The slope is dominated by censoring: at 9x9 c=11 and 10x10 c=12 every one of
  the 60 pairs is censored for both solvers at 1e6 nodes, and again under the
  preregistered extended cap (1e7 nodes, 180 s guard, which every run hit after
  1.3 to 4.6 million nodes). Those sizes therefore score log ratio 0 (ties)
  by the PROTOCOL.md rule and carry no information about the ratio. The
  secondary slope (extended rows substituted) is identical.
- Exploratory, not preregistered, not binding: restricted to the three sizes
  with at least 10/30 both-solved pairs (n = 6, 7, 8), the median log10 ratio
  goes -0.255, -0.379, -0.832 and the slope is -0.289 per n, 95% CI [-0.447,
  -0.101]. The n = 8 point is partly a bound (scb is censored on 10 of 30 pairs
  there, scored ln(bb/cap)), and three points on three different colour
  counts are thin. This is a lead for a follow-up with larger caps, not a
  finding.
- Q3 (descriptive only): see "Ablations" below.

## Arms and node rule

All arms run through hard-ladder's `NodeCounter` and `run_all`. One node = one
`NodeCounter::try_assign`, i.e. one (cell, piece, rotation) assignment the
search makes, counted before propagation. Forced cells (|D| = 1) and cells
reduced to one option by hidden singles are placed as explicit counted search
steps in every arm; propagation never places a cell without a node.

| arm | role | what it is |
|---|---|---|
| `bb-mrv` | binding | A16's `BbSolver { rule: Rule::Mrv }`, unchanged code (path dep on `../backdoor-branching/compute`) |
| `scb-gacolor_ac3_random` | binding | hard-ladder's scb wrapper semantics (run seed 1) with a wall-clock guard (`compute/src/scb.rs`) |
| `hp-dfs` | reference | hard-ladder's plain row-major DFS |
| `mrv-nohs` | exploratory | bb-mrv without piece-side all-different (hidden singles and the no-cell wipeout); piece singles kept |
| `mrv-bf` | exploratory | bb-mrv with border-first order: forced cells first, then min (class, \|D\|, index) |
| `mrv-rand` | exploratory | bb-mrv with scb's random value order (splitmix64, run seed 1) |
| `scb-ad` | exploratory | scb with A3's piece all-different (wipeout, hidden singles, piece singles) after AC-3, engine fork `compute/engine-fork` |
| `scb-fork-off` | check | the engine fork with the hook off |

Implementation checks (all in `results/summary.json` under `checks`, and in
`compute/tests/arms.rs`):

- the configurable propagator with hidden singles on equals
  `sat_backdoors::Model::propagate` exactly (unit test);
- `MrvSolver { Free, no random, hs }` equals A16's bb-mrv node for node (unit
  test, primary calibration n <= 7);
- the guarded scb wrapper and the fork with the hook off equal hard-ladder's
  scb node for node (unit test, and 20/20 identical rows on R6/R7 seeds 21..30
  against hard-ladder's committed `scb`/`hp-dfs` rows; `scb-fork-off` 20/20);
- `bb-mrv` rerun on A16's used seeds 1..20 (R6, R7, R8) reproduces A16's
  committed rows 60/60 (implementation check only; those seeds are not
  evidence here).

"Propagate calls per node" is 1.00 for every arm by construction (bb arms count
`propagate` calls, one per node plus one root call; scb places and propagates
once per node). The scb engine's native counter (pruned domain rows) is
reported as a separate unit, not comparable with the bb arms. The guard never
fired at cap 1e6 (0 time-censored runs); at the extended cap all 120 runs were
time-censored at 180 s.

## Exact commands

```
just experiments mrv-baseline            # = research/experiments/mrv-baseline/run.sh all
# stages: build | check | calibrate | q1 | q2 | extended | ablations | implcheck | analyze
```

`run.sh` skips any raw file that already exists, so on a clean checkout with the
committed results `all` rebuilds, tests and re-analyses (bit-identical
`summary.json`); delete `results/raw` to rerun everything. Single runs:

```
compute/target/release/mrv_baseline run --solver bb-mrv --ladder 8-c10-fresh --role test \
  --seeds 31-50 --cap 1000000 --guard 600 --threads 8 --out results/raw/bb-mrv/q1-r8b.jsonl
compute/target/release/mrv_baseline list
```

## Hardware and wall clock

Devin VM, Intel Xeon (8 vCPU), 31 GiB RAM, CPU only, 8 concurrent runs, one arm
at a time. Stage wall clock (`results/stage-times.txt`): calibration 657 s, Q1
binding 160 s, Q2 at 1e6 941 s, extended cap 2,880 s, ablations 406 s,
implementation check about 120 s; total about 86 min of runs. Wall-clock
ratios are measured under that concurrency; node counts are deterministic,
wall clock is not.

Calibration (seeds 1001..1010, cap 2e6, not used in any comparison): both
bb-mrv and scb solved 10/10 at n = 6 and 7 and 0/10 at n = 9 and 10.

## Ablations (exploratory, Q1 instances, descriptive only)

Paired against the parent (node ratio > 1 means the ablation needs more nodes):

| change from parent | R6 | R7 | R8 (30 pairs) | R8 wall ratio |
|---|---|---|---|---|
| bb-mrv minus hidden singles (`mrv-nohs`) | 1.31 | 1.53 | 1.11 [1.07, 1.19] | 1.33 |
| bb-mrv with border-first order (`mrv-bf`) | 1.15 | 1.10 | 1.83 [1.65, 2.08] | 2.13 |
| bb-mrv with random value order (`mrv-rand`) | 1.29 | 1.18 | 1.62 [0.89, 2.12] | 1.52 |
| scb plus A3 all-different (`scb-ad`) vs scb | 0.36 | 0.45 | 0.23 [0.20, 0.28] | 0.90 [0.79, 1.06] |

Reading (descriptive): no single removal from bb-mrv costs more than about 2x
in nodes at R8, while bb-mrv is about 7x below scb there; each ablated bb arm
still beats scb at R8 (ratios 0.16 to 0.26). Free MRV order (versus
border-first) is the largest single bb-side component at R8. From the scb
side, adding A3's piece all-different alone cuts scb's nodes about 4x at R8,
most of the gap, but the fork is slow per node (8.8k nodes/s against 33.6k), so
its wall-clock ratio is 0.90 with a CI reaching 1.06. The asymmetry between
`mrv-nohs` (keeps piece singles) and `scb-ad` (adds wipeout, hidden singles and
piece singles) is by design (PREREG.md) and limits how the two can be compared.

## Follow-up that would answer Q2 (not run here)

The binding Q2 result is uninformative above n = 8 because nothing solves 9x9
c=11 or 10x10 c=12 within the 1.3 to 4.6 million nodes the
extended runs reached before their 180 s guard. Answering whether the ratio
keeps shrinking needs caps around 1e8 to 1e9 nodes per board (hours per board
at 13k to 22k nodes/s), preregistered separately, for example:

```
compute/target/release/mrv_baseline run --solver bb-mrv --ladder plus2 --role test --sizes 9 \
  --seeds 1-30 --cap 1000000000 --guard 86400 --threads 8 --out results/followup/bb-mrv-n9.jsonl
```

(and the same for `scb-gacolor_ac3_random`, and `--sizes 10`).
